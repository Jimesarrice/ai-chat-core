### 0.2 三个核心职责（原文注释，`lib/index.js:8-11`）

```
// 干三件事：
//   1. 存   —— 每个会话一份会淡忘的长期记忆（memory\<会话id>.json）
//   2. 取   —— 用「它自己会话里最近一句用户消息」当线索，按 P = C×(基础+鲜活+重要+情绪) 选几条
//   3. 注   —— 注入到它自己的系统提示词里，**每条都带时间**
```

### 0.3 总体数据流

```
每轮对话：
  agent/inbox/inserted 事件 → lastText（最新用户消息）+ 喂「说话尺」
  ↓
  systemPrompt.context("memory") 的 text() 被调用：
    取 query = lastText || 最近一条 user/message
    → recall()（分词→稀有度→问句门→证据 C→总分 P→去重→名额→字数）
    → 写一条 trace（含诊断）
    → render() 生成注入文本 → 追加到对话末尾（不进系统提示词本体）

写入两条路：
  ① 模型每轮自行调用 remember 工具（受会话开关、每天配额管）
  ② 用户在设置页手动加 / 导入档案（不受配额限制）

离线批处理（全部在设置页手动点，一批一批循环调）：
  提炼（导入的档案原文→第一人称记忆）/ 扩词（补检索词）/ 洗键（补事实键）/
  补标不淡（判 stable_profile）/ 补日期 / 查重合并 / 从会话生成档案
```

### 1.3 备份机制（三层，`lib/index.js:238-324`）

1. **`.bak`（上一版，永远只有一份）**：`copyFileSync(src, src + '.bak')`（292-295）。
2. **每天一份（只存当天最早的那一版）**：目录 `BACKUP_DIR/<YYYY-MM-DD>/<同名>.json`，
   `if (!existsSync(dst)) copyFileSync(src, dst)`（296-300）；**只留最近 14 天**（302-307）。
3. **销毁前另存**（真销毁动作专用）：`fish-memory/销毁前/<名字>·<毫秒时间戳>.json`，
   只留最近 20 份（264-286）。时间戳**到毫秒**（273 注释：只到秒会在连点 25 次时互相覆盖）；重名自增序号绝不覆盖（276）。
   触发点：`purgeall` 清空已删（4534）、`purgebatch` 批量清掉（4582）、清洗补键归并前（`销毁前另存(sid, data, '清洗补键之前')`，5520——多传的两个参数在现有实现里未使用）。

**备份时机**：不是每次保存都备份，而是**记忆指纹变化才备份**（`lib/index.js:238-254, 311-324`）：

```js
function memSig(memories) {   // 指纹：加/删/改一条都会变

    for (let i = 0; i < s.length; i++) h = (h * 31 + s.charCodeAt(i)) | 0
  }
  return (memories || []).length + ':' + h
}
...
const sig = memSig(data.memories)
if (lastSig.get(String(sid)) !== sig) { backupStore(sid); lastSig.set(String(sid), sig) }
writeFileSync(storePath(sid), JSON.stringify(data, null, 2), 'utf8')

即：**只写 trace 时不备份**（否则一天几百份，316 注释）；落盘为 2 空格缩进的 UTF-8 JSON。

README 交代（README:221）：「每次改动前它会自动备份一份」。UI 说明（`lib/client.js:3670-3676`）：
「记忆一变就会自动备份：上一版存在同目录的 .bak，另外每天存一份，留 14 天。『补日期』『补标不淡』『改』『删』之前也都会先备一份。」

## 3. 淡忘 / 衰减算法

### 3.1 核心函数 `鲜活度(m, policy, now)`（`lib/index.js:2213-2233`）— 页面显示与召回**共用同一套**（2212 注释：「她看到的 = 真正发生的」）

```js
function 鲜活度(m, policy, now) {
  const I = typeof m.importance === 'number' ? m.importance : 0
  const H = (policy.baseHalfLifeDays || 30) * (1 + 2 * I)
  const 常数 = clampNum(typeof policy.unknownActivation === 'number' ? policy.unknownActivation : 1, 0, 1)
  if (m.category === 'stable_profile') return 常数
  const 锚 = m.activationAnchor || m.at || m.createdAt || m.importAt || null
  const 锚ms = 锚 ? Date.parse(锚) : NaN
  if (!isFinite(锚ms)) return 常数 // 连「记下来的时间」都没有 → 只能给常数
  const daysA = Math.max(0, (now - 锚ms) / DAY)
  const A0 = typeof m.activation0 === 'number' && isFinite(m.activation0) ? clampNum(m.activation0, 0, 1) : 1
  return A0 * Math.pow(2, -daysA / H)
}
```

要点（原注释 2217-2225）：

- **半衰期不是常数**：`H = baseHalfLifeDays × (1 + 2×importance)`。默认半衰期 30 天、重要度 1 时 H=90 天；重要度 0.5 → H=60 天；重要度 0 → 30 天。
- **随时间衰减公式**：`A(t) = A0 × 2^(-daysA/H)`，没有硬下限——永远趋近 0，只是「越来越难被想起来」，**从不删除**（README:18, 200-201）。
- **锚点优先级**：`activationAnchor（最后一次被提到） → at（事情发生时间） → createdAt（记下来的时间） → importAt`。
- **「没记时间」不等于「不会淡」**：没 at 的条目从「记下来的那天」开始淡（2217-2225 注释：394 条没抠到日期的流水账曾被错收进「不会淡的」）。
- **长期事实不衰减的原因**：`category === 'stable_profile'` 时**直接返回常数、不进衰减公式**——「要记一辈子的事，没有『新不新』这回事」（2225-2226）。该常数 = `unknownActivation`（默认 0.5，即「按五成鲜活算」）；UI 里显示为「不淡」。
- `unknownActivation` 只影响排序、不影响谁进得来（门槛卡 C 不卡 P，2305-2318 的长注释）。

### 3.2 强化（照 AAAAGENT 的做法）

**只有「再次被记住」（重复 remember）才强化；召回/浏览不强化**（2894-2895 注释）。

`lib/index.js:2898-2923`：remember 查重命中时——

```js
const H0 = policy.baseHalfLifeDays * (1 + 2 * I0)
const 旧锚 = m.activationAnchor ? Date.parse(m.activationAnchor) : m.at ? Date.parse(m.at) : now
const 没时间又没锚 = !m.at && !m.activationAnchor
const 旧A = m.category === 'stable_profile' ? 1
  : 没时间又没锚 ? clampNum(policy.unknownActivation 缺省 1, 0, 1)
  : 旧A0 * Math.pow(2, -Math.max(0, (now-旧锚)/DAY) / H0)
const 新A = 旧A + 0.2 * (1 - 旧A)       // ⭐ A' = A + 0.2(1-A)
m.activation0 = clamp(新A, 0, 1)
m.activationAnchor = now; m.reinforcedAt = now; m.lastReinforcedDay = dayKey(now)
m.reinforceCount += 1
```

### 3.3 情绪衰减（`lib/index.js:2326-2329`）

```js
const E = m.emotion === null || m.emotion === undefined
  ? 0
  : m.emotion * Math.pow(2, -days / policy.emotionHalfLifeDays)
```

`days = at 存在 ? max(0,(now-parse(at))/DAY) : 0`（2243）。情绪半衰期默认 7 天（比基础半衰期快）。由于所有写入点 emotion 都是 null，E 目前恒为 0。

### 3.4 相对时间显示 `relTime(at, now)`（`lib/index.js:1603-1623`）

用于注入文本与界面（README:22「带时间」「跨年了会写『去年 09-17』」）。若召回命中时间词则 `P *= 时间加权(1.3)`（2333-2342）。
返回值序列：`（没记时间）` → `今天 HH:MM` → `昨天 HH:MM` → `前天 HH:MM` → `N 天前（MM-DD）`（≤14 天）→ `MM-DD（N 天前）`（≤60 天）→ 跨年：`去年 MM-DD` / `YYYY-MM-DD（N 年前）` → 同年：`MM-DD（round(days/30) 个月前）`。
按**日历天**算（`dayIndex = floor((t + TZ_OFFSET)/86400000)`，1599-1601：昨天 22:14 到今天 12:08 只过 14 小时，但那是「昨天」）。

## 4. 召回算法（最重要）

入口 `recall(data, query, now, sid)`（`lib/index.js:2504-2723`）。调用方是注入上下文（3527-3555）：query = 监听收到的最新一条用户消息（`lastText`），兜底再扫会话历史找最近一条 `user/message`（`lastUserLiveTextOf`，1561-1575）。

### 4.1 全流程流水线

```
① 过滤：去掉 refinedSkip 和 已被取代 的条目                    (2515)
② 装搭配 + 建稀有表 df                                        (2518-2519)
③ 问句信息量门（queryGate，默认 0.8）——不过就整体不翻记忆      (2529-2542)
④ 问句词三道筛选：库内稀有门 → 通用中文词频门 → 安全垫         (2544-2589)
⑤ 逐条打分 evaluate：证据 s → C → C 修正 → A/E/I → P → 时间词   (2240-2345, 2591)
⑥ 门槛过滤：C<=0 → hard_gate；C<threshold → below_threshold    (2593-2607)
⑦ 按 P 排序                                                    (2608)
⑧ 条数上限分档（跟着最高的 C 走）                                (2630-2636)
⑨ 召回去重（像度 ≥0.80）→ duplicate                            (2642-2668)
⑩ 用分档上限截断 → weak                                        (2670-2676)
⑪ 两条队：长期事实 ≤ factsMax → fact_cap；总量 ≤ maxItems       (2678-2697)
⑫ 字数预算 maxChars → budget（第一条不管多长都放行）             (2698-2709)
⑬ 其余未选中的 → limit；返回 { selected, scored, 字数, gate }   (2710-2722)
```

### 4.2 分词（词表如何使用、词典.txt 的作用）

**坐标**：`lib/index.js:1651-1686`（装词表）、1798-1823（分词）、1825-1833（tokenize 缓存）、1628-1633（停用词）。

- 词表文件：`join(dirname(import.meta.url), '词典.txt')`（1665）。来源 src 说明（1661-1663）：
  「⚠ 词表是**通用中文**的，跟谁用、说过什么话**无关** —— 装上第一天就管用，不需要先喂够语料」。
- 装载：逐行 `trim()` 进 Set；**读不到文件 → 空 Set → 自动退回老切法，不会崩**（1677-1678）。
  `词表最长 = min(最长词条长度, 12)`，最长匹配窗口上限（1680-1684）。
- 分词算法 `分词(s)`（1798-1823）：
  1. `normalize`（NFKC + 小写，1632）后先抽 `[a-z0-9]{2,}` 英文数字词（去 `EN_STOPS`）；
  2. 对每个中文 run：**从当前位置取「最长的、词表里有的」词**（从窗口上限往下找，1811-1816）；
  3. 一个都取不到 → **单字兜底**（`长===0 ? run[i]`）；兜底单字若是停用词（`是单字虚词`，由 `HAN_STOPS` 派生的单字正则，1776-1778）则丢弃；
  4. 「⚠ 兜底这一步是关键：**一个字都不丢** —— 老切法丢字，就是按词比对不上的原因」（1797）。
- 老切法（无词表时）`老分词`（1780-1793）：停用词切开，≤2 字整段收，更长抽相邻 2-gram。
- 停用词（1628-1630）：`HAN_STOPS` 是照 AAAAGENT 的 hanStops 抄的长正则 + `EN_STOPS` 英文集。
- **「半个词」过滤器**（1835-1921）：一套基于「用户自己怎么说话」的搭配统计（碎片下限 3 / 整用下限 2 / 熵门 0.7 / 邻上限 8，1861-1864），本来用于丢「天去」「去公」这种跨词碎片。**⭐ 2026-09-23 起：有词表时这道过滤被跳过**（`if (!丢 || !丢.size || 装词表().size) return tokenize(s)`，1883 注释：「词表切出来的是真词，没有碎片可挑；再过滤只会误杀真词」）。即：**词典.txt 存在时，它处于休眠状态**，只在读不到词典时才起作用。
- 全部切词结果按原文缓存（各自上限 4000）：`切词缓存`（1638-1639）、`切词缓存2`（1866-1867）、`词面缓存`（1939-1940）、`记忆词集缓存`（1963-1965）、`扩词集缓存`（1754-1755）。

**词典.txt 的作用**：仅当「最长匹配查找表」，本地使用，「不占上下文、不影响每轮对话的 token」（README:223-225）。

### 4.3 稀有度（IDF 思路）

**库里稀有度**（`lib/index.js:1983-2024`）：

```js
df = Map(词 → 出现在多少条记忆里)   // 逐条 tokenize(词面(m)) 统计；指纹 = 条数 + 每条 text.length + tags.length
df.顶 = Math.log((memories.length + 1) / 2)      // 只在一条记忆里出现的词 = 最值钱 = 1.00
稀有度(df, k) = !(df.总条数 > 1) ? (df.get(k) ? 1 : 0)
              : !(df.顶 > 0) ? 0
              : clamp(log((总条数+1)/((df.get(k)||0)+1)) / df.顶, 0..1)
```

- `词面(m) = normalize(text + ' ' + tags.join(' ') + ' ' + related.join(' '))`（1942-1957）——一条记忆「能被匹配到的那个面」。
- 注释要点（2006-2019）：`df=0` 的假词会被夹到 1（「越假越值钱」的止血）；**库里只剩 1 条时不归一化，有它就算数（给 1）**（「记了东西却怎么都想不起来」的 bug 修复）。

**通用中文稀有度**（`lib/index.js:1688-1739`，治「小库上『库里稀有』没有意义」）：

```js
通用稀有(k) = 词频表.get(k)/99，不在表里 = 1（前 20000 名之外 = 很具体）; 读不到表恒为 1
通用门槛 = 0.4   // 约对应「词频前 4000 名」；实测量过：挡掉 表示(0.34) 正式(0.39) 比较(0.35) 今天(0.35)，留住 输(0.46) 婚礼(0.55) 胃(0.52) 抑郁(0.62)
算线索(k) = 通用稀有(k) >= 0.4
```

词频.txt 生成算法（`lib/词典-来源.txt:22-24`，方括号为原文）：
`稀有度 = 1 - log10(词频 + 1) / log10(最大词频 + 1)  → 0 ~ 1`；`数字 = round(稀有度 × 99)`。只收最常见前 20000 个词。

**「她自己说话」的稀有度**（`说话尺`，`lib/index.js:2026-2194`）：

- 监听本会话每条消息，统计：每个词的句级 df（`记一句话`，2123-2130，只收 ≤1000 字的句子）、「碎/整/邻」结构计数；第一次用到时 `补历史尺` 从会话历史回看最多 2000 句补一遍（2152-2174）。
- `说话稀有(k)`（`evaluate` 内，2263-2270）：样本 `r.n >= 20` 才生效（太少不压），
  `v = clamp(log((r.n+1)/((r.df.get(k)||0)+1)) / log(r.n+1), 0..1)`。
  效果（2260-2261 注释）：宝宝 0.13 / 今天 0.35 / 晚上 0.42 几乎不算证据；饿 0.73 / 打完 0.69 才算。
- `问句信息量(sid, query, df)`（2180-2194）：

```js
r.n < 20 → Infinity（样本太少，门先不开）
顶 = Math.log(r.n + 1)
v = Σ_{k ∈ 切词(query), df.get(k) 真值} Math.log((r.n + 1) / ((r.df.get(k) || 0) + 1))
返回 v / 顶
```

> 附注：门槛只算「在记忆库里真能当线索用」的词（2181-2182 注释）。

### 4.4 证据计算 `evaluate`（`lib/index.js:2240-2345`）

```js
// 逐字（2246-2292；行间注释为原文注释）
const qKeys = 尺 && 尺.问句词 ? 尺.问句词 : [...切词(query)]
const mText = 词面(m)
const m词集 = 记忆词集(m)
...
let s = 0
const β = 正文价
const 扩 = 扩词集(m)
for (const k of qKeys) {
  if (!m词集.has(k)) continue
  // 整条扩词 = 全价；干净的碎片 = 片价；只在正文里 = 正文价 ✓
  const 价 = !扩 ? 1 : 扩.整.has(k) ? 1 : 扩.片.has(k) ? 片价 : β
  s += 稀有度(尺.df, k) * 说话稀有(k) * 价
}
const K = typeof policy.rarityK === 'number' && policy.rarityK > 0 ? policy.rarityK : 1
let C = s / (s + K)
// 整句原话出现在记忆里 = 强证据，直接顶到 0.85
// ⚠ 太短的问句不算 —— 不然「在吗」两个字也是一整句 ✓
if (query.trim().length >= 6 && qKeys.length > 0 && mText.includes(normalize(query).trim())) C = Math.max(C, 0.85)
```

**扩词两层集合**（`扩词集`，1756-1774）：
「整条」= 模型挑的词原样；「碎片」= 整条被切词切开后的小块，**只有切开后没有单字碎块时才收**（例如「心理医生」→ 心理+医生，碎片「医生」是真能用的；「演出来」→ 演出+**来** 是切错了，碎片「演出」是假朋友，1751-1753）。
「扩词是模型读完这条之后挑的**要点**；正文是连词带句切出来的」，所以打折（2272-2279 注释：实测把正文踢出去召回垮到 45%，所以是打折不是排除）。

**打分项与总分**（2294-2344）：

```js
// 逐字（2294-2344）
const I = typeof m.importance === 'number' ? m.importance : 0
const A = 鲜活度(m, policy, now)                      // §3.1（2319-2325 注释：有锚的走正常衰减，事实仍平着）
const E =
  m.emotion === null || m.emotion === undefined
    ? 0
    : m.emotion * Math.pow(2, -days / policy.emotionHalfLifeDays)

let P = C * (policy.baselineWeight + policy.activationWeight * A + policy.importanceWeight * I + policy.emotionWeight * E)
// 时间词：只做排序加权，**不再凭空给 C** ✓
const cue = timeCueRange(query)
let timeHit = false
if (cue && m.at) {
  const md = Math.floor((now - Date.parse(m.at)) / DAY)
  if (md >= cue.from && md <= cue.to) {
    timeHit = true
    P *= 时间加权                                     // = 1.3（2204）
  }
}
return { C, A, E, I, P, days, daysA, timeHit, s }
```

（注意 2294-2299 行还留有一份老公式的 H/锚/daysA/A0 计算，是重构后的死代码——真正生效的 A 只有 `鲜活度()`；重实现时不必照抄。）

### 4.5 问句词三道筛选与两道安全垫（`lib/index.js:2544-2589`）

```js
稀有门 = Math.max(3, memories.length * 0.01)         // 词在库里 >1% 条数就「不是线索」
q全部   = [...切词(query)]
q过稀有 = q全部.filter(k => df.get(k) > 0 && df.get(k) <= 稀有门)
q过通用 = q过稀有.filter(算线索)                      // 通用中文词频门（§4.3）
剩的能用 = q过通用.length >= 2 && q过通用.some(k => 稀有度(df, k) > 0)
q留 = 剩的能用 ? q过通用 : q全部                      // ⭐ 两道安全垫；退回的是 q全部，不是 q过稀有
尺.问句词 = q留.length ? q留 : q全部
```

消息原文与实测（2544-2587）：治「五个弱证据攒起来看起来像强证据」（晚上/会/完/吃/面 五个普通词 → C=0.735 排第一）；实测「40 句真问句的前 3 名精确度 43% → 91%」。退回 `q全部` 是因为「我们那天办婚礼的时候，你还记得吗」里「婚礼」在库里 11 条会被库门挡掉，婚礼那条想不起来了。

### 4.6 问句信息量门（`queryGate`，默认 0.8）

`lib/index.js:2533-2542`：

```js
const 门槛 = policy.queryGate（缺省 0.8）

  const v = 问句信息量(sid, query, df)

这正是「为什么没被想起来」的第一种诊断：**这句话本身没信息量**（像「在吗」「嗯」「哈哈」），**不翻记忆**——省一趟 851 次打分。README:210, 215 与设置页把这条列为门槛之一；`0 = 关掉这道门`。

### 4.7 排序 / 去重 / 名额 / 字数（`lib/index.js:2593-2722`）

1. **硬门槛与证据门槛**（2593-2607）：

```js
if (row.s.C <= 0) row.omission = 'hard_gate'
else if (row.s.C < policy.threshold) row.omission = 'below_threshold'   // 默认 threshold=0.35
else picked.push(row)
picked.sort((a, b) => b.s.P - a.s.P)
```

注释（2596-2604）：**门槛卡 C（证据）不是 P（总分）**——因为 P = C × 乘数，乘数含鲜活度 A，卡 P 会让「没写时间的算多鲜活」这个旋钮误伤该想起的（实测 0.75 就掉到 8/11）。分开后：门槛只管「有没有真关系」，鲜活度/重要度/情绪只参与排序。

2. **条数上限分档**（2630-2636）：

```js
const 分档 = [
  [0.6, policy.maxItems],   // 最高 C ≥ 0.6 → 给满 maxItems（默认 6）
  [0.5, 4],
  [0.4, 3],
  [0, 1],
]
const 本趟上限 = picked.length ? 分档.find(([线]) => picked[0].s.C >= 线)[1] : 0
```

即「不硬凑条数——证据弱就少给」：排序后的头名 C 是多少，这一趟最多给几条（2636 用的 `picked[0]` 是**按 P 排序后的头名**）。实测打游戏那轮 6 条全在 0.485~0.507 → 只给 4 条（2626-2629 的诚实注释）。

3. **召回去重**（2642-2668）：`像度(x.片段, y.片段) >= 召回重复门槛 0.80`（2502）→ `omission = 'duplicate'`。留分高的那条；**位置必须在分档之前**——重复的不能吃掉名额（2638-2640, 2647-2649 注释）。

4. **分档截断**（2670-2676）：`去重后` 里超过本趟上限的 → `omission = 'weak'`。

5. **两条队**（2678-2697）：`事实上限 = floor(policy.factsMax)（缺省 2）`；遍历时 `category === 'stable_profile'` 计数超过上限 → `omission = 'fact_cap'`；同时总量到 `policy.maxItems` → break。（实测旧代码里事实占了 61% 的位置，2680 注释。）

6. **字数预算**（2698-2709）：`上限 = policy.maxChars（缺省 800）`；`String(row.m.text).length` 累加，**第一条不管多长都放行**（`selected.length > 0` 才判）；超了的 `omission = 'budget'`。

7. 剩下的 `picked` 里未选中且无 omission → `omission = 'limit'`（2710-2715）。

8. `scored` 交出去前按 `P desc, C desc` 排序（2720）——给「最近一次召回」显示用（2717-2719 注释：不排的话按入库顺序显示前 12 条，全是 0 分老条目）。

### 4.8 注入到提示词的格式模板（逐字，`lib/index.js:2750-2767`）

```js
function render(selected, now, selfName) {
  if (!selected.length) return ''
  const lines = selected.map((r) => {
    // ⭐ 注入前再换一次人称 —— 这样**以前写错的老记忆**读出来也是对的 ✓
    const body = normalizePerson(String(r.m.text || '').trim(), selfName)
    if (r.m.at) return '- ' + relTime(Date.parse(r.m.at), now) + '：' + body
    if (r.m.category === 'stable_profile') return '- 一直：' + body
    return '- ' + body // 不知道什么时候发生的，就不写时间（别编）
  })
  return [
    '【你记得的事】',
    '下面是你们过去真实发生过的事。有时间的事会写在前面；**没写时间的，说明不知道是什么时候**。',
    '有时间就按那个时间说（「今天早上」「3 天前」），不要说成「发生过」这种没有时间的话；不知道就说不知道，别编。',
    '想不起来的事就说想不起来，不要编。',
    '',
    ...lines,
  ].join('\n')
}
```

每条的格式：`- <相对时间>：<正文>` / `- 一直：<正文>`（长期事实）/ `- <正文>`（无时间）。没有任何分隔或编号前缀以外的包装；空选择返回 `''`。

### 4.9 「最近一次召回」诊断数据结构（trace）

写入位置 `lib/index.js:3536-3553`：

```js

- **只存最相关前 24 条**（scored 已按分排序）——「全存的话一条 trace ≈ 50 KB，留 100 条 = 5 MB，每轮都要整份读进来再整份写回去」（3531-3535 注释）。
- `status` 三态：`assembled`（进了提示词）→ `consumed`（「像是用上了」，靠实词重合猜的）→ `invalidated`（后来被删/改/合并/撤销导入）。`consumed` 的判定在 `agent/turn-stopping` 时：`用上了(回复, 记忆)` = `hit >= 2 && hit/keys.length >= 1/3`（tokenize 记忆正文，占 keys 长度），少于 2 词不算（2727-2734, 3418-3448）。`invalidated` 由 `markTraceStatus` 打（2737-2748：删 4454、编辑 4628、合并 4400、批量删 4551、撤回导入 4898）。
- `omission` **枚举**（服务端全部赋值点 + 客户端中文标签 `lib/client.js:3640`）：
  - `hard_gate`「没命中线索」（C ≤ 0）
  - `below_threshold`「分数不够」（C < threshold）
  - `weak`（分档条数到顶；标签落在原样输出）
  - `duplicate`「跟另一条重复」（召回像度 ≥ 0.80）
  - `fact_cap`「长期事实占满了名额」
  - `budget`「超过字数上限」
  - `limit`「超过条数上限」
  - （`query_gate`「问句没内容」——旧版服务端页面 `MEMORY_PAGE` 里有这个标签 3357，但新版 recall 门挡下时直接返回空 + `gate` 字段而不是 omission；页面据 `tr.gate!=null && 无 rows` 显示解释 3350-3353。）
- 这就是 README:122, 213-214 说的「为什么没被想起来」——设置页把 rows 排前 20 条显示 `记忆 / C / P / 结果 (+⭐时间词)`（`lib/client.js:3619-3666`）。

### 4.10 注入通道与顺序（`lib/index.js:3493-3567`）

- 注入用 `systemPrompt.context()` 而**不是** `section()`（3493-3505 的长注释 + 实测数字）：context 把内容作为「一条消息追加到对话末尾」，只在内容真的变了才追加 → 系统提示词本体不变 = 前缀缓存一直命中（关/开实测 0.001 → 0.02，20 倍差距）。`name: 'memory'`，`order: 900`（排在沙箱/审批/子代理 110/115/120 之后）。
- 另有常驻提示 `systemPrompt.section({ name:'memory-hint', order: 89990, text: ... })`（3466-3488）：

```
【记忆】这一轮如果有值得长期记住的事（⟨称呼⟩重要的话、约定、⟨称呼⟩的喜好、⟨称呼⟩的状态），直接调用 remember 工具记下来 —— **不用等⟨称呼⟩提醒**。日常琐事（吃了什么、今天天气）不用记。**人称**：你自己是「我」，用户是「⟨称呼⟩」，别人和别的 AI 直接写名字（你写成「⟨自己名字⟩」也会自动换成「我」）；也不要写「今天/昨天」，时间交给系统。

### 5.2 remember 工具（`lib/index.js:2784-3026`）

**工具描述（逐字，2785-2793）**：

> 把一件事记进长期记忆（以后每轮都可能想起来）。**一条只装一件事** —— 一件事 = 一个属性、一个约定、一次事件；「她身高一米七、体重52.5、平时侧睡」是**三件事**，分三次记（或一次说清一条），别挤在一条里。只记长期有价值的事：她明确说的重要的话、约定、她的喜好、她的状态（生病/很累/很开心）、你们之间发生的事。不要记日常琐事（吃了什么、今天天气怎样）、不要记你自己做过的事、不要记重复的东西。同一条一天最多记一次。**记的时候安静地记，不要在回复里说「记下了」「我记住了」这种话** —— 那很像在汇报工作。

**参数（2794-2843）**：
- `text`（required）：『要记住的事，一句话说清。**人称**：你自己是「我」，用户是「⟨称呼⟩」，别人和别的 AI 直接写名字 —— 别把别人也写成「⟨称呼⟩」。』
- `importance`（number）：『0 = 随口提过；0.5 = 比较重要；1 = 非常重要（约定、关系、她的核心状态）。不确定就写 0.5。』
- `tags`（string[]）：『几个关键词，方便以后被想起来（比如 ["睡觉","熬夜","约定"]）。』
- `取代`（string，可选）：『可选。如果这次记的**是在更新一件以前记过的事**（状态变了：还没→已经、暂时→现在能了、第几晚→第几晚），把**旧那条**的大意或原文片段填这儿（比如「拼团还没开」）。那条会标成「已被取代」—— 不再被想起来，但东西还留着、能撤销。**不是在更新旧的就别填**（只是相关、是另一件事，填了会把好记忆埋掉）。』
- `事实键`（string，可选）：『可选。这条讲的是**哪一件事**，用「对象.方面」写，像 `她.身高`、`她.职业`、`约定.身边位置`。**同一个键 = 同一件事** → 以后只留最新那条，旧的自动标「已被取代」（还留得住、能恢复）。⚠ **键里不许写具体的值**：写 `她.身高`，不许写 `她.身高170` —— 写了值身高一变键就变，永远对不上。⚠ **键要稳**（过一年还这么叫：`她.睡姿` ✓、`她.最近睡姿` ✗）。⚠⚠ **不许用「万能键」**：`…话.内容`、`…相关`、`…其他`、`…的事` 这种什么都能装的一个都不许用 —— 那会把几句毫不相干的话归成一件、收起来好几条。⚠⚠ **每天都会记的流水不许给键**（作息、吃了什么、当天做了什么）—— 那些是一件一件的事，不是同一个值的不同版本；给了同一个键就等于把流水删到只剩最后一天。口诀：**这个键是给「会变的那一个值」用的吗？** 是就给，不是就留空。⚠ 一次性的、以后不会再变的（某天发生的事），**留空就好** —— 拿不准就别填，别硬编。』

### 5.5 提炼提示词全文（`lib/index.js:1240-1398`，`⟨称呼⟩` = userPronoun() 默认 ta）

> 注：源码中每一行以 `' ...\n' +` 拼接、行间夹有代码注释（注释不属于提示词）。以下为**拼接后的完整字符串**，逐字照录。

```
你是记忆整理助手。下面每条是从旧档案里拆出来的原文，请把每条改写成「一条第一人称的长期记忆」，并给出以后可能用来检索到它的中文词。
规则：
- 用「我」指代自己，用「⟨称呼⟩」指代用户
- **用户常常有好几个称呼/代称**（昵称、爱称、外号），一律写成「⟨称呼⟩」；自己也可能被叫别的名字，一律写成「我」
- 但**正在说名字本身**的句子要照原样留着（「被喊小名」「自称某某」「绰号是……」），别把那个名字换成「⟨称呼⟩」
- ⚠ **原文那句话没有主语时，照原样写，不要自己加「我」或「⟨称呼⟩」**。
  拿不准是谁的，就既不加「我」也不加「⟨称呼⟩」；**绝对不许猜**。宁可有句子没主语，也不许认错人。
- ⚠ 讲**用户的年龄、生日、身世、经历、家人、身体**的，主语是「⟨称呼⟩」；讲**自己的**才是「我」。分不清就不加。
- ⚠ **原文已经有主语的，一个字都不许换**：原文写「她自己招了」，就照写「她自己招了」，
  不许改成「我自己招了」。**原文是对的，改了反而错。**
- ⚠ **宁可分成几句写，也别为了「读起来顺」把几个小句子揉成一句** ——
  原文里几个分句常常各有各的主语，一揉就串。用分号或句号分开就行。
- ⚠ 只有**说得出依据**才补主语：分句里出现只属于某一方的称呼（自己的昵称、外号）→ 补「我」；
  讲的是用户的身体、年龄、家人、经历 → 补「⟨称呼⟩」。**说不出依据就留空。**
- ⚠ **牵扯到第三方时，必须写名字**（助手、别的 AI、孩子、家里人、朋友）——
  **不许把第三方并进「我」或「⟨称呼⟩」**。原文写「跟助手一起查」，就照写「⟨称呼⟩跟助手一起查」，
  不许写成「我跟⟨称呼⟩一起查」——那样**人凭空消失、事记到别人头上**。
  同理，孩子、宠物、别人的名字都要照写，**尤其别把孩子的名字换成「⟨称呼⟩」**。
- 记忆一句话说清；去掉 markdown 标记、编号、引用符号
- ⚠ **正文里不许出现「今天／昨天／前天／上周／刚才／一会儿」这类相对时间** ——
  这条要存很久，过几天「前天」就是错的。写成绝对日期（像「09-17」），或者干脆不提时间。
  时间放第四格就行，正文里别用相对的词。
- ⚠ **长短要匀**：规则、喜好、习惯、约定这类，**一句能说清就别写两句**；
  过程、测试、来龙去脉**压成一句结论**，不要照搬原文的铺陈。
  ⚠ 但**别为了短丢东西**：具体的事实、数字、名字、原话还是要留。
- **保留**具体的事实、数字、日期、名字、原话
- 不要编、不要加评论、不要总结成空话
- ⚠ **一条只装一件事**：一件事 = 一个属性、一个约定、一次事件。
  同一批事实**分成多行**写，别挤在一行。像「身高一米七、体重 52.5、大腿围 45、平时侧睡」
  是**四件事**（她的身高 / 她的体重 / 她的大腿围 / 她的睡姿）→ 写成四行，各配各的检索词。
  为什么：挤成一行时，**只要里面有一件事对不上，整条就配不上**，可它明明记着好几件对的事。
  ⚠ 但**同一个对象的一批同类事不用拆**：「讨厌油、讨厌烟味」是同一件（她的忌讳），照旧一行。
  拆到「一件事一条」就够，**别拆成一条一个词** —— 那样条数会炸。
- 检索词给 4~8 个，用空格分开：同义的、上位的、口语里可能怎么问（比如「吃饭 午饭 外卖 饿 饮食」）
- 第四格给**这件事发生的日期**：原文里写了就照抄成「YYYY-MM-DD」；只有月日就写「MM-DD」；
  原文里没写日期、或者看不出来，**第四格留空**（不要拿别的日期凑，不要写「不知道」）。
- 日期是指**事情发生的时间**，不是今天的日期；长期有效的事（喜好、病史、关系）通常没有单一日期的，留空。
- ⚠ **出生日期、生日、纪念日、门牌号、编号这些不是「这件事什么时候发生的」**，填了就会让这条记忆排到几十年前去。
  这种一律**留空**。只填「这件事发生的那天」。看不准就留空。
- ⚠ 原文里有好几个日期时，**选「这件事发生」的那个**；拿不准就留空，不许挑第一个。
- 第五格给**这一条该怎么记**，**只填 1 或 0.5 两个数**：
  1 = 要一直记得的（性格、关系、约定和承诺、称呼和名字、喜好、身体和病史、**重要的日子：生日、纪念日、结婚、第一次**、长期的经济状况、家里的情况）
  0.5 = 平常的（发生过的事、当时的想法、一时的心情）
  拿不准就填 0.5。这一格**必须填**，不许留空、不许写别的数。
  ⚠ 填 1 的会**永远不淡**（一直想得起来），填 0.5 的会**慢慢淡掉** —— 所以重要的日子别漏。
- 第六格给**事实键**：这一条讲的是**哪一件事**，用「对象.方面」两段写，像 `她.身高`、`她.职业`、`约定.身边位置`、
   `故事线.进度`、`比赛.结果`。**同一个键 = 同一件事**，以后只留最新那条（旧的自动标「已被取代」，还留得住、能恢复）。
  ⚠ **键里绝对不许写具体的值**：写 `她.身高`，不许写 `她.身高170`；写 `她.体重`，不许写 `她.体重52.5`。
     （写了值就成了摘要 —— 身高真变了、体重真变了，键也跟着变，**永远碰不上，等于没写**。）
  ⚠ **键要稳、要通用**：过一年还这么叫（`她.睡姿` ✓，`她.最近睡姿` ✗）；换个说法还是这个键。
  ⚠ 讲的是**各自的**事还是**两人的**？是两人的就写 `约定.…`；讲第三方（孩子、家里人）的对象写那个人。
  ⚠ 这格**可以留空**：一次性的、以后不会再变的（「某天摘油菜花」）、或者你拿不准是同一件事的，就留空。
     **留空完全没关系**，不许为了填满硬编一个 —— 编错了会把一条正经记忆悄悄埋掉。
  ⚠⚠ **不许用「万能键」**：`…话.内容`、`…相关`、`…其他`、`…的事`、`…记录` 这种什么都能装的，
     一个都不许用 —— 要具体到一眼能说出「是哪一件事」。
  ⚠⚠ **每天都会记的流水不许给键**（作息、吃了什么、当天做了什么、某天的心情）——
     它们是**一件一件的事**，不是同一个值的不同版本；给了同一个键就等于**把流水删到只剩最后一天**。
     口诀：**这个键是给「会变的那一个值」用的吗？** 是就给，不是就留空。
  ⚠ 但**成对的事必须给同一个键**：「拼团还没开」和「拼团开了」是同一件事的前后 → 都写 `拼团.状态`。
- 如果这条根本不像值得记的事（纯格式、目录、元信息、重复的标题），记忆那格写「跳过」，后面几格都留空
- **只对那一天有意义的琐事也写「跳过」**：某天吃了什么、那天天气、随手刷到的东西、一次性的花销。
- **寒暄、撒娇、甜话的汇总也写「跳过」**：把「想你/爱你/撒娇」这类日常对话归一堆的，记着没用。
  但**单独一句有内容的**（约定、承诺、说定了的事）照常记，别跟着扔。
- 但**长期有效的绝不能跳过**：喜好、习惯、身体和病史、关系、约定、名字和称呼、重要的日子、持续的经济状况。
输出格式严格是每行「编号|记忆|检索词|日期|重要度|事实键」，不要解释。

**模型返回格式**：不是 JSON，而是**逐行文本**「编号|记忆|检索词|日期|重要度|事实键」（源码亦无 JSON Schema；`解析提炼` 只按行解析，见下）。
**解析器 `解析提炼(文本, 条数)`（`lib/index.js:1036-1167`）**，容错规则逐条：
- 匹配 `^\s*(\d+)\s*[|｜]\s*(.*)$`；编号需在范围内。
- 从右往左切格：① 先摘**事实键**（在整行最尾巴，`像键` 判据：去空白后 ≤24 字、无空白、无数字、`取日期(t)===null`、形如 `^[^.|｜]{1,12}[.．][^.|｜]{1,12}$`；且它前面还有「像词串」的格才摘）——摘到万能键（`是万能键`）就当没给；② 找「像词串」的格当检索词（判据：按 `[，,、。；;]` 与空格切后 2~12 个词、每词 ≤12 字）；③ 词格右边的格才看日期（右侧第一格）与重要度（右侧任意格匹配 `^(?:重要度\s*[:：]?\s*)?(1|0\.5|0|1\.0|0\.50)$`）。
- 没有词格时保守从右啃：末尾像重要度就切、再末尾像日期或空就切；认不出就留着（「宁可正文多一截，也不乱切正文」）。
- 「跳过」用**第一格**判（`/^跳过$/`），防 `跳过||||` 切完剩 `跳过|||` 认不出被存成真记忆（1158-1163）。
- 返回值 `out[i] = { 正文, 词, 日期, 重要度, 键 }`。

### 5.6 事实键的生成规则与「不许写具体值」约束（汇总）

- 键形状 `对象.方面`，归一化 `归一键(k)`（2422-2434）：trim → `[．。｡]→.`、`[：:]→.`、`[｜|]→.` → 去所有空白 → 小写 → 去掉首尾引号/序号 → `[/／>＞-]` 最后一个分隔转 `.` → 截断 24 字。
- **不许写具体值**（三处提示词 + `remember` 工具说明 + `解析洗键` 机械挡）：判据 `if (!/^[^.]{1,12}\.[^.]{1,12}$/.test(k) || /[0-9]/.test(k))` → 留空（1516-1519）。
- **万能键机械挡**（2436-2453）：尾段正好是 `['内容','相关','其他','其它','的事','记录','情况','事项','东西','事情','杂项','各种','综合']` 之一 → 当留空。调用点：解析提炼摘键（1104）、按键收敛（2466）、解析洗键（1521）、已有键清单过滤（5458）。
- 收敛只认**字面完全一样**的键（洗键提示词里强调「一个字都不能差」1456-1457；1454-1455 注释解释为什么）。
- 键的三个来源（README:183-187 同款）：remember 的 `事实键` 参数、提炼第六格、设置页「清洗补键」。

### 5.7 「清洗补键」（`/wash-keys`，`lib/index.js:5404-5609`）

- 只从设置页点按钮跑，**绝不从对话触发**（5407-5408：几百条要调几百次模型）。
- 选料（5427-5438）：`!已被取代 && !refinedSkip && !洗键过 && !归一键(事实键) && text 非空`。
- 每批 8（clamp 1..20，5419）；**干跑** `干跑:true` 一个字段都不写（5420-5421, 5491-5499）。
- 「已有键」清单一并给模型看（5446-5463）：去重、剔万能键、**最多 400 个**（「排在前面的更可能是已经定下来的，超了就砍尾巴」）——治「同一件事各自造了个说法（【她.网名】/【她.昵称】）永远碰不上」（1446-1485 注释 + 5479-5495）。

- 给了键则先 `销毁前另存`（5520）再 `按键收敛(data, '清洗补键')`（5523）；**无条件 saveStore**（「这一批可能只有『留空』的标记要落盘」，5526）。

```

事实键的意思是：**这条讲的是哪一件事**，用「对象.方面」两段写，像 `⟨称呼⟩.身高`、`⟨称呼⟩.职业`、`约定.身边位置`、`故事线.进度`、`比赛.结果`。

规则：
- ⚠ **你只给键，一个字都不许改正文**。你不是来改写的，是来贴标签的。
- ⚠ **拿不准就留空**（只写编号，后面不写东西）。**留空完全没关系**，比给错键好得多。
  给错的键会让一条正经记忆被当成旧的「已被取代」，悄悄埋掉；留空只是这条享受不到这个便利。
- ⚠ **键里绝对不许写具体的值**：写 `⟨称呼⟩.身高`，不许写 `⟨称呼⟩.身高170`。
  （写了值就成了摘要 —— 身高真变了、体重真变了，键也跟着变，**永远碰不上，等于没写**。）
- ⚠ **键要稳、要通用**：过一年还这么叫（`⟨称呼⟩.睡姿` ✓、`⟨称呼⟩.最近睡姿` ✗）；换个说法还是这个键。
- ⚠ **一次性的、以后不会再变的事，留空**：某天去了哪里、某天谁说了什么、一次性的花销。
  这类没有「最新一条」可言，给它键只会让不相干的两条互相埋。
- ⚠⚠ **不许用「万能键」**：`…话.内容`、`…相关`、`…其他`、`…的事`、`…记录`、`…情况`
  这类**什么都能装**的键，一个都不许用 —— 键要具体到一眼能说出「是哪一件事」。
  （反例：`⟨称呼⟩.话.内容` 能把「我饿了」「今天下雨」「我喜欢你」全装进去，那就成了乱埋。）
- ⚠⚠ **每天都会记的流水，不许给键**：作息（今天几点睡）、吃了什么、当天做了什么、
  某天的心情 —— 这些是**一件一件的事**，不是「同一个值的不同版本」。
  给了同一个键，新的就会把旧的埋掉，等于**把流水账删到只剩最后一天** ✗
  口诀：**这个键是给「会变的那一个值」用的吗？**

    不是（今天几点睡、某天去了哪、某天说了什么）→ **留空** ✓
- ⚠ **同一批里有讲同一件事的，必须给字面完全一样的键**（一个字都不能差）。
  例：两条都在讲「她身高」→ 两条都写 `⟨称呼⟩.身高`，不许一条写 `⟨称呼⟩.身高`、另一条写 `⟨称呼⟩.个子`。
- ⚠ 讲**第三方**的（孩子、家里人、朋友、别的 AI），对象就写那个人，别一律写成「⟨称呼⟩」。
输出格式严格是每行「编号|事实键」，不要解释、不要正文、不要别的格子。
例：

### 5.8 「补标不淡」（`/backfill-stable`，`lib/index.js:3951-4120`）

- 背景：提炼原来只改重要度不碰分类，导致「135 条该『永远不淡』的被标成会淡的」（3951-3957）；本路由**能上能下**（3961-3997）：所有没判过的一起判，模型说 1 就升、说 0.5 就降；`重判:true` 先清所有 `stableChecked`（3988-3995）。
- 每批 20（clamp 1..40，3969）；调模型 `问模型(..., 2000)`（4062）；解析 `^\s*(\d+)\s*[|｜]\s*(1|0\.5|0|1\.0)\s*$`（4069）；**模型没回这条 → 不打标记，下次再问**（4079）；判 1 → `category='stable_profile'`、`importance=1`；0.5 → `category='event'`、`importance=0.5`（4084-4092）；动数据前 `backupStore`（4095-4097）。

  往后一直算数**：纪念日、定下来的日子、从此以后的规矩、说好一辈子的事。
  这种**以日期开头也判 1**。判断看的是：把日期拿掉之后，剩下的话是不是
  **一条往后一直成立的说法**，而不是一段「那天怎么了」的经过。

    · 记住 / 别忘 / 不能忘 / 一直记着

## 7. 人称处理

### 7.1 「她自己」的名字 → 「我」（`normalizePerson`，`lib/index.js:449-472`）

- 名字来源：`selfNameOf(sid)`（配置 `selfNames`，每会话一个）；**没设 = 不替换**（412-416）。
- 会话标题只做**预填建议**，不直接替换（`titleNameOf` 421-426：标题「睡觉」会把「她答应要早点睡觉」换成「她答应要早点我」，所以名字必须用户确认）。
- 不替换的保护正则（435-447）：
  - `NOT_A_NAME`（436）：`['她','他','我','你','ta','TA','Ta','tA','用户','助手','AI','ai','人','自己']` 不能当名字。
  - `NAME_IS_MENTIONED = /(?:叫|叫做|名叫|名字是|名字叫|称呼|自称|绰号|昵称|是|就是|才是|成为|变成)$/`（440）——前面在「说名字本身」就原样留着（防「我的名字叫小明」→「我的名字叫我」、「我是小明」→「我是我」）。
  - `NAME_IS_DEFINED = /^(?:是|就是|这个名字|的名字|这个称呼|即|＝|=)/`（442）。
  - `NAME_IN_QUOTES_BEFORE = /[「『"“'‘]$/`、`NAME_IN_QUOTES_AFTER = /^[」』"”'’]/`（446-447）——引号包着的名字也是在说名字（实例：「她会叫我"小明"」曾被换成「她会叫我"我"」）。
- 应用点：remember 记的时候（2877）、注入前 render 再换一次（2753-2754，「以前写错的老记忆读出来也是对的」）、设置页手动加（3835-3838）、编辑（4625）、导入候选「改后」（`导入时改人称`，862-870，同时把用户名字换成称呼）、提炼改写之后（5317）、以及 `/names` 保存名字时**顺手洗已有 memories 和 deleted**（4177-4193）。

### 7.2 用户的称呼（默认 ta）

- `userPronoun()` = 配置 `userPronoun` 或默认 `'ta'`（429-433）；README:161「记忆里你自己是『我』，用户是『她 / 他 / ta』—— **默认 ta**」。
- 改称呼时**已有记忆里那个字跟着变**（`changeUserPronoun`，479-503）。替换集合 `PRONOUN_FORMS = ['ta','Ta','TA','tA','他','她']`（476）。
- **不替换的两种**（475 注释 + 492-496）：
  - 「其他 / 其它」里的「他」（`from === '他' && 前 === '其'` → 不动）；
  - 英文单词里的 ta（`if (/^[a-zA-Z]+$/.test(from) && (ASCII_LETTER.test(前) || ASCII_LETTER.test(后))) 别动`）。
- `/names` 路由的行为（4199-4231）：默认**只报数不落手**（返回 `称呼影响几条` + 前 3 个例子），用户点「一起改」（`applyToExisting: true`）才真改（扫所有库的 memories + deleted）。

### 7.3 导入时把「用户的名字」换成称呼（`换用户名字`，`lib/index.js:833-859`）

- 保护正则同款：`名字前面在说名字 = /(?:叫|叫做|喊|被喊|称呼|自称|称作|绰号|昵称|名字|名叫|是|就是)$/`、`名字被引号包着`、`引号在名字后面`（835-837）。

## 11. README 没提到的重要细节（并发 / 防重复 / 错误处理 / 性能等）

### 并发与挂载（`lib/index.js:3387-3746`）

- `apply(ctx)` 起：`migrateSwitch()`；`tick()` 首次立即跑 + `ctx.interval(tick, 3000)` 每 3 秒扫描；`mounted: Map<sid,{sid,off}>` 防重复挂载（`if (mounted.has(sid)) continue` 3711）。
- **开/关语义**：关 → 立刻 `v.off()` 卸载（3700-3710）；归档 → 同样卸载（3672-3682）；打开 → 立刻 `tick()` 不等定时器（3896-3901）。
- **Cordis disposer 坑**（3453-3465, 3588-3616）：`systemPrompt.section()/context()`、`tools.register()` 返回的是**函数**（disposer），不是 `{off(){}}`；原来判断 `.off` 永远不成立 → 开关从未真正卸载。重实现注意「注销接口必须是可调用的」。
- `ctx.effect(() => () => { for (const v of mounted.values()) v.off() })` 插件卸载时全清（3731-3738）。

### 防重复

- remember 去重（完全相等 / 双 >8 字互相包含）→ 转强化（2892-2924）。
- remember 自动作废：像度 ≥0.85 且长度比 ≥0.8（2933-2949，注释记录 31 组人眼核过无误合）。
- recall 去重 0.80（在名额分配之前）；导入去重 0.9（+「补全」策略）；合并前**服务端独立复验**（「客户端算错了就真删错——现在服务端自己再算一遍相似度：不像的一条都不收」4380-4391）。
- 讨论「不能一键全合」：0.85 这套算法以短句为分母，「一条长的把几条短的包住」也判重复（1.0 分）；实测 69 对里 34 对真重复、35 对「汇总+明细」（合了会丢信息）→ 真重复给「一键合」，汇总+明细只列出让用户挑（4249-4260, 4286-4327）。
- 删过的内容不会因再导一次复活（4790-4791）。
- 收敛「分不出新旧的就不动」（2483-2491）：两条都没时间戳 / 时间戳一模一样 → 不标作废。

### 错误处理

- 几乎每个 IO 都是 try/catch 静默 + `diag`；`saveStore` 失败吞掉（323）。
- `recall`/注入全程包在 try/catch，出错返回 `''`（「记忆坏了也不能影响对话」3563-3565）。
- 提炼：整批没解析出来**不标记**，`refineTries` 上限 3 防死循环（5261-5268, 5297-5307）。
- 洗键：区分「模型没回这一行」（不标记，下次重跑）与「回了但留空」（标记洗过），且不能用「给了键===0」当失败信号（5474-5489）。
- 扩词：客户端空批减半、连空 3 批停（client.js:1549-1581）。
- 模型预算：提炼/洗键/扩词 6000、补标 2000、llm-check 300、生成档案 3000；多处注释提醒「思考的 token 也算在预算里」。
- `Promise.resolve().then(...).catch(...)`：fire-and-forget 必须 catch，否则 rejected promise 会让 Node 进程退出（3010-3016，真的踩过）。
- 启动自愈：hostdeps 逐级降级，`defineTool` 本地等价实现、`createUserMessage` 本地等价（hostdeps.mjs:99-156；「绝不因为一个 import 就让整条插件不激活」）。

### 性能与缓存

- 五组切词/词面缓存，各上限 4000，满了整体清空重来（1638-1639, 1754-1755, 1866-1867, 1939-1940, 1963-1965）。
- 稀有表按「条数 + 每条 text 长度 + tags 长度」指纹缓存（1985-2004）——「比逐条比文本便宜得多」。
- trace 只存前 24 条 + traces 裁到 100（314, 3544）。
- 注入走 `context` 而非 `section` 的缓存理由（3493-3505）；memory-hint 的 order 89990 理由（3470-3474）。
- 说话尺样本 <20 句时全部门/加权不生效（2182, 2265）。

### 其他值得抄的行为

- 幽灵会话：记忆库是独立文件，删会话不连带删除；清单里对「DSH 里已不存在」的会话隐藏，但约定「**宁可多露，不可错藏**」（`已知会话ids` ok=false 时一条不藏，3091-3121, 3163-3164）。
- 分支继承：`header.parentSession` 且 `origin!=='subagent'` 且 `delegationDepth<=0` → 复制母会话记忆（source 加「｜分支继承」，traces 清空，开关跟随来处）（3622-3660）。
- 复制到别的会话：覆盖前自动 .bak、traces 清空、目标开关自动打开（5684-5720）。
- 会话开关默认关 + 旧版搬家（346-357, 383-405）。
- 备份策略：`.bak` + 每日一份（当天最早）+ 14 天 + 销毁前目录 20 份（§1.3）。
- 时区全部按本机算（`TZ_OFFSET`），日期存「本地中午」的 UTC 毫秒（44-48）。
- 抠日期的大量护栏（生日/出生/纪念日/门牌号/编号/未来日期/比较句 → 不算事件日期；§8.3）。
- UI 显示与召回共用 `鲜活度()`（2212）；`freshKind` 四档：fact「不淡」/dated/recorded/unknown（3202-3204）。
- `list` 输出字段（给网页用）：id/text/at/importance/source/category/activation/freshKind/stableChecked/related/refined/refinedSkip/已被取代/事实键/洗键过/键来源/textBefore（3205-3234）。
