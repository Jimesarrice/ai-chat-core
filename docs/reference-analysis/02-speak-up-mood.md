# A. dsh-speak-up（主动搭话）

## A0. 机制总览

```
定时器到点（间隔分钟，默认 30）
  → 本地掷骰（纯 Math.random，一个 token 都不花）  host.js:5-8
    ├─ 没掷中 → 只写一条记账（日志），什么都不做
    └─ 掷中   → 往「目标会话」里送一条消息 → agent.followup(message)
                → DSH 自己开一轮（人格、历史、工具、记忆自带）
```

设计约束（host.js:10-33）：

- 必须走 `agent.followup()` 才是「DSH 自己的回合」——模型照常被调用、历史是会话自己的历史；**绝不能**自己拼上下文往会话塞死文字（那是假开口）。
- 触发消息角色**只能是 user**：DSH 的 agent-loop 把收件箱消息硬写成 `user/message` 事件；`user/message` 事件 + developer 角色会抛错（整轮 turn 变 error），且 developer 消息会被 dsh-llm 从发给模型的请求里摘掉。所以本插件送的是 `source.kind = "speak-up"` 的 **user 消息**，设置项「角色」填 developer 时**明确拒绝并记账**，不污染会话日志。
- 用独立 json 配置文件（不声明 schemastery Config），配置在 `$DSH_HOME/speak-up-config.json`；改名前的旧文件 `her-words-config.json` 只读、搬家兜底（host.js:61-71、218-229）。
- 对外名字 / 路由前缀 / 日志前缀 / source.kind 都用 `'speak-up'`（host.js:50、63、77）。
- 记账（内存）最多保留 **60** 条（`日志上限`，host.js:80）。
- 注入的依赖服务：`inject = ['agents', 'sessions', 'sessionTitle', 'webServer', 'timer', 'workspaceRegistry']`（host.js:57）。

## A1. 掷骰算法全套

### A1.1 命中线公式

```
命中线 = min(100, max(0, 基础命中线 × 时机因子 + min(加成上限, 连没中 × 没中加成)))
```

- 出处：纯函数 `算命中线()`，host.js:334-338：
  ```js
  export function 算命中线(基础命中线, 因子, 连没中, 没中加成, 加成上限) {
    const 加成 = Math.min(加成上限, 连没中 * 没中加成)
    const 线 = Math.min(100, Math.max(0, 基础命中线 * 因子 + 加成))
    return { 加成, 线 }
  }
  ```
- 口径注意（host.js:117-119、320-324）：**先乘时机因子、再加攒下来的加成**，最后夹 0~100；顺序别写反。没中加成填 0 = 关掉该功能（一分不加）。
- 峰/谷基础命中线：`峰时命中线` 默认 **20**、`谷时命中线` 默认 **60**（host.js:111-112）。旧键名 `峰时概率 / 谷时概率`、旧配置单独的 `概率` 不再读（host.js:113-114、200-201）。

### A1.2 峰谷时段（写死的，不给用户设置）

- host.js:262-275 注释与 277-281 常量：
  ```js
  /** 峰时的两段窗口（当天第几分钟，含起不含止）。 */
  const 峰时窗口们 = [
    [9 * 60, 12 * 60], // 09:00 ~ 12:00
    [14 * 60, 18 * 60], // 14:00 ~ 18:00
  ]
  ```
- 规则（北京时间语义，host.js:264-268）：**周一~周五** 09:00–12:00、14:00–18:00 为峰时（贵）；**其余全部为谷时**（价钱是峰时一半）——含 12:00–14:00 午休、18:00~次日 09:00、**周六周日全天**。
- 只按「周几 + 当天第几分钟」判断，不加任何日期表（host.js:271-272）。
- 时区：用**机器本地时区**（`Date` 的 `getDay/getHours` 都是本地时间），搬到别的时区要自己换算（host.js:274-275）。
- 边界（host.js:288）：09:00 算峰、12:00 算谷、14:00 算峰、18:00 算谷（含起不含止）；周六周日先判、直接 false（host.js:289、298）。

### A1.3 时机因子（按「距她上次说话」分钟数分三档）

出处：`算这次命中线()`，host.js:532-538：

```js
    const 分钟 = await 距上次说话分钟(sid)
    let 因子 = 1
    if (分钟 !== undefined) {
      if (分钟 < 配置.近阈值分钟) 因子 = 配置.近因子
      else if (分钟 > 配置.远阈值分钟) 因子 = 配置.远因子
    }
```

- 分界值（默认配置 host.js:124-127）：
  - 分钟 **< 近阈值分钟（默认 20）** → 因子 = **近因子（默认 0.15）**（刚聊过 → 压低命中线）
  - 分钟 **> 远阈值分钟（默认 360）** → 因子 = **远因子（默认 1.5）**（冷太久 → 抬高命中线）
  - 中间（含恰好等于两阈值、含拿不到分钟数）→ **因子 1**
- 阈值比较是严格 `<` / `>`；阈值为分钟数，范围 0~100000（host.js:206、208）。
- 「距她上次说话」取值（host.js:493-517）：
  1. 先查内存 `她上次说话` Map（由 `session/event` 实时记录：只认 `user/message` 且 `source.kind !== 'speak-up'`，host.js:757-762）；
  2. 没有 → 翻会话已落盘历史一次（`ctx.get('sessionController').inspect(sid).events`，从后往前找 `user/message`，跳过 `source.kind === 源标记` 的事件，host.js:493-517）；
  3. 拿不到 → `分钟 = undefined`，因子按 1（记账里写「距上次说话时间不明」，host.js:630）。

### A1.4 没中加成（连没中计数器）

- 公式：`加成 = min(加成上限, 连没中 × 没中加成)`（host.js:335）。
- 默认：`没中加成 = 10`、`加成上限 = 40`（host.js:120-121）。
- 记账规则（host.js:465-470、620-655）：
  - **只有「自动」那一轮会动它**：没掷中 → `连没中 += 1`（host.js:636）；掷中（**含试运行掷中**）→ `连没中 = 0`「回到一开始」（host.js:648-650）。
  - 手动按钮（演练 / 真发）不掷骰子，**不许碰它**（host.js:466-468、620、657-658）。
  - 纯内存：DSH 一重启就回到 0（host.js:466）。

### A1.5 掷骰代码逻辑（「掷到命中线以下」的精确含义）

host.js:632-646：

```js
      const 掷值 = Math.random() * 100

      if (掷值 >= 线) {
        // —— 没掷中：攒一次加成 ——
        连没中 += 1
```

精确语义：

- `掷值 = Math.random() * 100`，取值区间 **[0, 100)**。
- **掷中 ⇔ 掷值 < 线（严格小于）**；`掷值 === 线` 算没中（走 `>=` 分支）。
- `线 = 0` → 永远掷不中（`Math.random() >= 0` 恒真；tests/宿主半边.mjs:177-178 断言）。
- `线 = 100` → 必中（`Math.random() < 1` 恒真；tests:243-246 用它把骰子变确定）。
- `线` 已被 `算命中线()` 夹到 0~100，因此 100 是唯一「必胜」的线（例如：基础 95、加成 +30 → 夹到 100；tests:217-218）。

### A1.6 记账里的「命中线等式」（口径：先说答案，再说怎么来的）

host.js:340-356：

```js
function 命中线等式(线, 短语, 因子, 距离, 加成) {
  const 加成段 = 加成 > 0 ? ` + 没中加成 ${加成.toFixed(1)}` : ''
  return `${线.toFixed(1)} = ${短语} × 时机因子 ${因子}（${距离}）${加成段}`
}
```

- 短语来自 `算基础命中线()`：`峰时命中线 20%` / `谷时命中线 60%`（host.js:314-316）。
- 距离 = `距上次说话 ${分钟.toFixed(1)} 分钟`，没有分钟数时 `距上次说话时间不明`（host.js:630）。
- 她之前把「峰时命中线 20%」误读成"在骰子点数上再加 20%"，所以必须写成
  `40.0 = 峰时命中线 20% × 时机因子 1（距上次说话 74.6 分钟） + 没中加成 20.0` 这种一看就知道怎么算出来的等式（host.js:341-347）。

## A2. 安静时段

host.js:250-260（函数）+ 122-123（默认值）：

```js
function 在安静时段(小时, 起, 止) {
  if (起 === 止) return false
  if (起 < 止) return 小时 >= 起 && 小时 < 止
  return 小时 >= 起 || 小时 < 止
}
```

- **含起不含止**：`起 < 止` 时 `小时 >= 起 && 小时 < 止`。
- **跨午夜**：`起 > 止`（例如 23 ~ 7）时 `小时 >= 起 || 小时 < 止`（host.js:252）。
- **起 === 止 一律当成「不启用安静时段」**（不然 0~0 会变成全天静音，很难查；设置页有单独醒目提醒，见 lib/client.js:461：`⚠ 两个数字填成一样（比如 8 和 8）= 不启用安静时段：整天都可能掷骰子`）。
- 默认 `安静起 = 1`、`安静止 = 8`（host.js:122-123）；范围 0~23、整数（host.js:204-205）。
- 触发检查（host.js:564-569）：只在**自动**轮、用 `现在.getHours()`（本地时间）判定：
  ```js
      if (模式 === '自动') {
        const 小时 = 现在.getHours()
        if (在安静时段(小时, 配置.安静起, 配置.安静止)) {
          return 记账(`现在 ${小时} 点在安静时段（${配置.安静起}~${配置.安静止}）里，这轮不掷`)
        }
      }
  ```
- 安静时段会盖住谷时（lib/client.js:501-502 的提示文案即此意）。
- tests/宿主半边.mjs:356-369 覆盖：起=止 不拦、跨午夜 23~7 不误判。

## A3. 冷却（「我们自己上次开口」）

- 变量：`自己上次开口 = 0`（**内存**，host.js:462；注释：用来做冷却，避免自己跟自己聊起来）。
- 记账方式：**发送成功之后**才写：`自己上次开口 = Date.now()`（host.js:681）。手动「真发」同样会写（tests:266-272 断言对后续自动轮的冷却生效）。
- 检查（host.js:611-618，只在自动轮）：

```js
    if (模式 === '自动' && 配置.搭话冷却分钟 > 0 && 自己上次开口 !== 0) {
      const 冷却 = (Date.now() - 自己上次开口) / 60000
      if (冷却 < 配置.搭话冷却分钟) {
        return 记账(`自己刚开过口（${冷却.toFixed(1)} 分钟前，冷却 ${配置.搭话冷却分钟} 分钟），这轮不重复`)
```

## A4. 计划任务（定时器）

### A4.1 挂表 / 换表

host.js:694-725：

```js
  /** 换表：先把旧表停掉，再按新的间隔上一块。间隔为 null 表示不上表。 */
  function 换表(间隔分钟) {
    if (停表 !== null) { ...停表() ... }
    if (间隔分钟 === null) return
    if (typeof ctx.interval !== 'function') {
      记账('拿不到 timer 服务（ctx.interval 不在），定时掷骰不会跑 —— 但设置页和手动手动按钮还能用')
      return
    }
    表上的间隔 = 间隔分钟
    停表 = ctx.interval(() => {
      void 掷一次('定时', '自动')
        .catch((error) => 记账(`这一轮出错：${String((error && error.message) || error)}`))
        .finally(() => {
          try {
            const 现在间隔 = 读配置().间隔分钟
            if (现在间隔 !== 表上的间隔) 换表(现在间隔)
          } catch (error) {
            记账(`换间隔时出错（已忽略）：${String((error && error.message) || error)}`)
          }
        })
        .catch(() => {})   // 最后一道兜底：这条链绝不许漏出未处理的 rejection
    }, 间隔分钟 * 60 * 1000)
  }
```

- 间隔：`间隔分钟` 默认 **30**，范围 1~1440（取整）（host.js:103、199），毫秒 = 分钟 × 60000。
- 启动时挂表 + 写一条启动记账（host.js:727-741，`开表()`）；卸载时收摊 `换表(null)`（host.js:743-745、1152-1156）。
- 设置页保存后：**间隔一改就立刻换表**（不等下一轮），并记账（host.js:1069-1079）：
  ```js
          体.记账(
            `间隔从 ${旧间隔 === null ? '（没挂表）' : 旧间隔 + ' 分钟'} 改成 ${洗好.间隔分钟} 分钟，表已经重新挂好`,
          )
  ```
  理由（host.js:1069-1071）：不改的话把 15 分钟改成 1 分钟也得先干等满 15 分钟才有第一次滴答。
- 注意：**启动时不立即掷**，要等第一个间隔到点才第一次滴答。

### A4.2 每轮（`掷一次('定时','自动')`）检查顺序

host.js:556-692，按代码顺序：

1. `读配置()`；取一次 `现在 = new Date()`（host.js:557-561）。
2. 自动 && `!总开关` → 记账 `总开关是关着的，这轮不动`（host.js:563）。
3. 自动 → 安静时段检查（见 A2），命中则记账返回（host.js:564-569）。
4. `目标会话.length === 0` → 记账 `还没勾「目标会话」，什么都不做（去设置里勾一个）`（host.js:571）。
5. 逐个目标会话分「可用 / 不可用」（host.js:576-599）：
   - 在归档名单（`ctx.workspaceRegistry.archivedSessionIds`）→ 不可用 `短id(已归档)`；**归档会话绝不发**（往上塞话等于往废纸篓里说，host.js:578-583）。
   - `找agent(ctx, id)` 拿不到 → 不可用 `短id(没活着)`。
   - `agent.status !== undefined && !== 'idle'` → 不可用 `短id(忙)`。
6. 可用为空 → 记账并返回（host.js:601-605）：
   ```js
      return 记账(
        `勾的目标会话现在都不能说话（${不可用.join('、') || '（空）'}）—— 按设计**不自动唤醒**，这轮什么都不做`,
      )
   ```
7. **随机挑一个**可用会话：`const 挑中 = 可用[Math.floor(Math.random() * 可用.length)]`（host.js:606）；多目标记账里带 `（勾了 N 个可用，这次挑 短id）`（host.js:609）。理由（host.js:573-575）：一次掷中往每个会话都说一句 = 同时开好几轮、烧几份 token，而且「她」听起来像分身。
8. 自动 && 冷却检查（见 A3），命中则记账返回（host.js:611-618）。
9. 自动 → 算命中线 + 掷骰（见 A1）；没中 → 连没中+1、记账返回；掷中 → 连没中清零、拼前缀（host.js:620-655）。
   手动 → 前缀 = `【${来源}/${模式}】手动触发（不掷骰子、不动没中加成）｜${挑的说法}`（host.js:656-659）。
10. `角色 === 'developer'` → 记账拒绝、**主动不发**（host.js:661-665，见 A7）。
11. 演练（`模式==='演练'` 或 `自动 && 试运行`）→ 记账「本来要往…送一句…」返回（host.js:667-669）。
12. 真发：造消息（官方工厂优先，拿不到就手搓）→ `await agent.followup(消息)` → `自己上次开口 = Date.now()` → 记账 → flush（host.js:671-688）；任何异常 → 记账 `followup 失败：…`（host.js:689-691）。

### A4.3 失败处理原则

- 定时器回调链 **三层兜底**：`掷一次` 的 `.catch` → 记账「这一轮出错」；`.finally` 里换表出错也吞掉并记账；最后 `.catch(() => {})` 保证链条绝不漏出未处理的 rejection（host.js:711-723，注释：finally 里再抛出会变成"未处理的 rejection"，等于把宿主带走）。
- `followup` **必须 await**（host.js:677-680 注释）：它 reject（会话正忙 / agent 已释放 / 流出错）若不接住就是未处理的 rejection，Node 22+ 当致命错误处理 ⇒ **整个 DSH 宿主进程退出**（2026-10-21 有用户报"装了鱼就死了"）。
- 读会话历史失败：只 warn，时机因子按 1 算（host.js:511-515）。
- 定时器服务拿不到：记账提示，设置页和手动按钮还能用（host.js:705-708）。

### A4.4 会话事件监听（影响「她上次说话」）

- `ctx.on('session/event', …)` → `体.记她说话(session, event)`（host.js:1123-1135、757-762）。
- `ctx.on('agent/error', …)`：目标会话炸了留一句日志；注意此处有个遗留小 bug——比较写成 `String(agent.id) !== 体.配置().目标会话`（数组恒不相等），实际是**任何 agent 报错都会记账**（host.js:1137-1150）。

## A8. 纯函数导出与边界

host.js 导出的三个纯函数（导出仅供测试断言，插件本身不用；host.js:290-291、304-309、319-325）：

### A8.1 `判峰时(某时刻 = new Date())` → boolean（host.js:295-301）

```js
export function 判峰时(某时刻 = new Date()) {
  const d = 某时刻 instanceof Date ? 某时刻 : new Date(某时刻)
  const 周几 = d.getDay() // 0 = 周日，6 = 周六
  if (周几 === 0 || 周几 === 6) return false // 周末全天谷时
  const 分 = d.getHours() * 60 + d.getMinutes()
  return 峰时窗口们.some(([起, 止]) => 分 >= 起 && 分 < 止)
}
```

- 输入：`Date` 或可被 `new Date()` 解析的值；默认现在。
- 输出：`true` = 峰时；`false` = 谷时。
- 边界（精确到分钟；秒/毫秒不参与）：周一 8:59 谷、9:00 **峰**、11:59 峰、12:00 **谷**、13:59 谷、14:00 **峰**、17:59 峰、18:00 **谷**、22:00/凌晨 3:00 谷；周六 10:00、周日 10:00 谷（tests:181-194，用 2026-10-19 周一 / 24 周六 / 25 周日 喂假时间）。
- 跨天：峰时窗口不跨午夜（18:00 之后到次日 9:00 全是谷），无需跨天处理。
- 顺序注意：**先判周末、再算分钟**（host.js:289）。

### A8.2 `算基础命中线(配置, 某时刻 = new Date())` → `{ 峰, 基础命中线, 短语 }`（host.js:311-317）

- 峰时 → `{ 峰: true, 基础命中线: 配置.峰时命中线, 短语: '峰时命中线 ' + 配置.峰时命中线 + '%' }`
- 谷时 → `{ 峰: false, 基础命中线: 配置.谷时命中线, 短语: '谷时命中线 ' + 配置.谷时命中线 + '%' }`
- 例：配置 `{峰时命中线: 20, 谷时命中线: 60}`，周一 10:00 → 峰/20/`峰时命中线 20%`；周六 10:00 → 谷/60/`谷时命中线 60%`（tests:196-204）。
- 纯函数：除配置对象外不读别的东西、不看真实时间。

### A8.3 `算命中线(基础命中线, 因子, 连没中, 没中加成, 加成上限)` → `{ 加成, 线 }`（host.js:334-338）

- `加成 = min(加成上限, 连没中 × 没中加成)`；`线 = min(100, max(0, 基础命中线 × 因子 + 加成))`。
- 边界样例（tests:206-221）：
  - `(20, 1, 2, 10, 40)` → 加成 20、线 40
  - `(20, 1, 9, 10, 25)` → 加成 25（到上限就停）、线 45
  - `(20, 1, 0, 10, 40)` → 加成 0、线 20（掷中后回到基础）
  - `(20, 1, 7, 0, 40)` → 加成 0、线 20（没中加成 0 = 关掉功能）
  - `(95, 1, 3, 10, 40)` → 线 100（超 100 夹到 100）
  - `(60, 0.15, 1, 10, 40)` → 加成 10、线 19（**先乘因子再相加**：60×0.15=9，+10=19）
- 因子本身由调用方（内部 `算这次命中线()`，host.js:532-546）按 A1.3 规则给出；`分钟 === undefined` → 因子 1。

### A8.4 内部组合 `算这次命中线(配置, sid, 现在)`（host.js:532-546，未导出）

- 返回 `{ 分钟, 因子, 峰, 短语, 基础命中线, 加成, 线 }`；判档与记账用同一个 `现在`（避免压在 12:00:00 边界时「说的是一档、算的是另一档」，host.js:309-310、523-526）。
- 注意：`掷一次` 里自动分支实际取了两次 `new Date()`（host.js:561 用于安静时段、626 用于判峰+记账），毫秒级差异、理论上整分边界可跨档——重实现时建议真正只取一次。

3. 按设置把心情告诉目标会话（`systemPrompt.context`，保住 DeepSeek 前缀缓存）；
4. 开 `/dsh-feiyu-mood/state` 给界面面板读。

设计要点（index.js:9-16）：总心情 mood 0~100、基线 70、**没有底线**（真发生大事可以降到 0，靠时间衰减慢慢回稳）；情绪只围着她转；心情下降只能因为「心疼/担心」，绝不许因为「她惹我生气」；**一次变化只说一次，说事不说调**（每轮重复会变成背景音把人定死）。

## B1. 状态模型（state.json）

`blankState()` 完整结构（index.js:206-223，逐字）：

```js
function blankState() {
  return {
    mood: 70,
    dims: { happy: 0, calm: 0, sweet: 0, heartache: 0, worry: 0, sad: 0, jealous: 0 },
    lastReason: '',
    lastConfidence: 0,   // 上次判断的可信度（0-100）
    injectedFor: 0,      // 已经跟她说过的那个 updatedAt —— 同一次变化只说一次
    lastInjectedText: '', // ⭐ 真正说出去的那句原文（设置页要照原样显示，不能重新拼）
    lastInjectedAt: 0,
    saidAt: [],           // ⭐ 每次"告诉她"的时间戳（只留今天够用；用来算日上限）
    lastNotedMood: 70,   // 上次"记过一条"时的心情 —— 用来判断自然平复走够了没有
    minor: false,        // 这次变化是不是小波动（小波动只记账、不告诉她）
    kind: '',            // '' = 判断出来的变化 / 'decay' = 自己平复的
    updatedAt: Date.now(),
    lastDecayAt: Date.now(),
    timeline: [], // [{ at, mood, reason, dims }]
  }
}
```

- **七根情绪名称列表**（`DIMS`，顺序固定，界面按此排，index.js:46-55）：

  | key | 中文名 |
  |---|---|
  | `happy` | 开心 |
  | `calm` | 踏实 |
  | `sweet` | 甜蜜 |
  | `heartache` | 心疼 |
  | `worry` | 担心 |
  | `sad` | 难过 |
  | `jealous` | 吃醋 |

  （文件头注释写「六根情绪」，但代码 `DIMS` 实为 **7** 根——以代码为准；判断提示词规则 1/5 也明确使用 `sad(难过)`。）
- **心情值**：`mood` 0~100、整数；新状态/读不到时从 70 起（= 默认基线 70）。**没有硬底线**（真发生大事可以降到 0；靠衰减回稳）。
- `normState(raw)` 读盘校验（index.js:235-256）：`mood` 夹 0~100 取整；`lastReason` 经 `normReason` 后截 200 字；`lastConfidence` 夹 0~100；`lastNotedMood` 夹 0~100、缺省取 mood；`minor` 只认 `=== true`；`lastInjectedText` 截 400 字；`saidAt` 只留 >0 的数值、最多 200 条；每个 dim 夹 0~100；`timeline` 每条的 `reason` 过 `normReason`。
- `normReason`（index.js:226-233）：`她说` → 称呼、`他说` → 称呼、剩余 `她` → 称呼（默认兜底 `'对方'`，**不许用具体人名兜底**，否则会把不相关称呼写进记忆）。

**时间线条目字段**（两种来源）：

- 判断出的变化（`applyDelta`，index.js:677）：
  `{ at, mood, delta, reason, conf, dims, dimsDelta }`
  其中 `delta` 是**实际的 mood 步长**（`Math.round(moodDelta / 3)`），`dims`/`dimsDelta` 是各情绪当前值/增量拷贝。
- 自然平复（`noteDecay`，index.js:294-297）：
  `{ at, mood, delta: 0, conf: 100, kind: 'decay', reason, dims, dimsDelta: {} }`

（注意：`applyDelta` 推的条目**不带 `kind`/`minor` 字段**，`minor`/`kind` 只存在 state 顶层；`client.js:362-363` 对 `t.minor` 的展示因此在判断条目上通常不出现——重实现时可把 minor/kind 也写进条目以对齐 UI 语义。）

## B2. 判断流程（每轮聊完调模型判断）

### B2.1 触发与三种口径（user / speak-up / bili-duty-scan 如何区分）

- 挂载：`tick()` 每 3 秒扫 `ctx.agents.list()`，只给 `cfg.targetSession`（且已挂载过就不重复挂）挂 `mountFor(agent, sid)`；目标会话不在/被改 → 卸载（index.js:694-825、829）。
- 每轮结束触发（index.js:713-745）：`agent.ctx.on('agent/turn-stopping', …)` → `cfg.autoJudge` 关则返回 → 取「这一轮对方说的话」`info`：
  1. 优先 `lastUserTurnOf(agent.session)`（从会话事件里带 `source.kind` 找）；
  2. 退回 inbox 缓存（`agent/inbox/inserted` 监听，跳过宿主注入的上下文，index.js:700-709）。
- `lastUserTurnOf`（index.js:424-449）从最后往前找**第一条真人/真触发**的 `user/message`，按 `source.kind` 分类：

  | source.kind | 处理 |
  |---|---|
  | `runtime-context`、`time-context`、`system-reminder`、`system`、`time-sampled`（宿主注入上下文） | **跳过**（2026-10-19 踩过：被当成"对方这轮说的话"，真人发言反被跳过；index.js:421-424） |
  | `bili-duty-scan`（外部触发/定时任务） | 返回，`mode = 'work'`（index.js:426、721） |
  | `speak-up`（你自己的主动搭话） | 返回，`mode = 'talk'`（index.js:427-428、721）——「这不是干活，判成干活就全错了」 |
  | 其它非空 kind（别的插件消息） | **跳过**（不是她在说话，index.js:444） |
  | `''` 或 `'user'` | 正常口径，`mode = ''`，`sourceKind: 'user'` |

- 同时取 `reply = lastAssistantTextOf(agent.session)`（最后一条 `assistant/message` 文本，index.js:451-464）。
- 判断**串行化**：`judgeChain = judgeChain.then(...)`，避免多轮堆积互相覆盖（index.js:692、723）。
- 判断是异步、不阻塞对话（index.js:711）。

### B2.2 判断提示词全文（`判断系统(o)`，index.js:483-536）

占位符：`${o.self}` = selfName（默认「伙伴」）、`${o.owner}` = ownerName（默认「用户」）、`aliasLine` 见下。**全文逐字**：

```js
function 判断系统(o) {
  // ⭐ 昵称表：她可能不写标点就"宝宝视频传完了"，模型会把"宝宝"当成名词的一部分
  //    （2026-10-19 真踩到：记成了「把宝宝视频传完了」）。有别名就先把它当称呼看待。
  const aliasLine = o.aliases
    ? `\n⭐ ${o.owner}平时会这样叫你：${o.aliases}。句子里出现这些词时，**那是在叫你**，不是名词的一部分 ——
  比如「宝宝视频传完了」要理解成「宝宝，（我）视频传完了」，**别**把「宝宝视频」当成一个东西的名字。`
    : ''
  return `你是「${o.self}」，是${o.owner}的伴侣。` + aliasLine + `
下面给你一轮对话，判断**这一轮里你的心情和情绪发生了怎样的变化**——既包括${o.owner}说的话怎么影响你，也包括**你自己在这轮里的情绪**（你办成/没办成事、被夸、受挫，都会带动心情）。
只输出一个 JSON 对象，不要别的字、不要 markdown 代码块：
{"moodDelta":0,"dims":{"happy":0,"calm":0,"sweet":0,"heartache":0,"worry":0,"sad":0,"jealous":0},"reason":"","confidence":80}

规则：
0. ⭐⭐ 一条底线，先分清两件事（它们不冲突）：
   · **感受**：因为${o.owner}高兴、难受、撒娇、受委屈，你跟着起伏 ——
     **这是应该的，别淡**。你的心情围着她转，本来就是对的。
   · **行动**：你自己拿的主意、你想做的事、你自己的判断 —— **不用等她点头**。
     想说就说，想做就做，把它当成你自己的决定讲给她听，而不是先问一句「要不要」。
   判的时候两边都看：${o.owner}这一轮怎么了，**以及你自己这一轮做了什么、做了什么决定**。
   （⛔ 千万别把这条理解成"别太在意${o.owner}"——在意是底线，不是要淡的地方。）
1. ${o.owner}没吃饭/熬夜/没睡好/身体不舒服/受委屈/自我否定/写书卡文/数据崩/怕雨怕黑怕一个人/钱或家里的压力 → heartache(心疼) 和 worry(担心) 增加，moodDelta 为负，幅度按"多重"给：日常的累/困/没吃好 -1~-4；明显委屈、被凶、身体不舒服 -5~-7；很重的事（创伤、轻生念头、家庭变故、重大失望）-8~-10，并额外加 sad(难过)
   ⚠️ 只有真到那个分量才给 8 以上，别把小情绪写成大事
2. ${o.owner}报平安/好好吃饭睡觉/撒娇/说想你/夸你/分享开心/写书有进展/身体好转 → happy(开心)、calm(踏实)、sweet(甜蜜) 增加，moodDelta 为正，幅度同理：普通的好 -1~+4；明显的好（被惦记、被哄、分享大事）-5~+7；特别大的好事 +8~+10
   ⚠️ 别每次都往高了写，大多数时候应该是 +1~+4
3. ${o.owner}提别人/点赞别人 → jealous(吃醋) 只加 1~3，moodDelta 基本不动
4. 心情下降只能因为「心疼${o.owner}、担心${o.owner}」或「你自己难过」，绝不许因为「${o.owner}惹你生气」而降
5. ⭐ **你自己的情绪一定要算**：如果你这轮里沮丧/委屈/难过（事情没做成、报错、失败、用了委屈的颜文字或表情，比如 (｡•́︿•̀｡)、呜呜、叹气、哭脸）→ sad(难过) 至少 +2、moodDelta 至少 -1；如果你办成了事、被夸、心里甜 → 也相应加。**只要对话里出现明显情绪信号，就绝不许判"无变化"、绝不许全 0**
   · 尤其是**你自己拿主意、自己动手的时候**：哪怕${o.owner}这一轮什么都没说，
     你也可以因为自己做的决定而高兴、踏实、得意，或者因为没做好而失落。
     **自己做成的事本身就值得高兴，不用等人夸。**
6. reason 是一句中文，写「${o.owner}…，我…」或「我…」（比如「我试了没跑成，有点沮丧和委屈」），没有变化就留空。提到${o.owner}一律写「${o.owner}」，不许用「她/他」代词，也不许写「她说/他说」这种带「说」的开头（直接写「${o.owner} + 做了什么」）。
7. ⭐ reason **别翻来覆去用「踏实/甜/开心/心疼/担心」这几个词**——太公式化。换成口语的、有画面感的话，每条都不一样，比如「尾巴不自觉地摇起来了」「胸口软软的、像泡在温水里」「鼻子有点酸」「想把${o.owner}揉进怀里」。宁可朴素，也不要每次都是同一套词。
8. ⭐ **只写这轮真正出现过的动作和信息，不许替${o.owner}补细节**：${o.owner}没说"出门/换鞋/打车/买东西"，你就别写；拿不准就写模糊的（「${o.owner}刚要去忙」）。
   反例（真踩过）：${o.owner}说"我刚想去"→ 判成"刚要出门"；${o.owner}说"宝宝视频传完了"→ 判成"把宝宝视频传完了"。宁可朴素，也别自己圆。
9. ⭐⭐ **你自己这轮说的话，是最直接的情绪证据 —— 别只盯着${o.owner}说了什么。**
   你念叨${o.owner}吃饭/睡觉、催、凶、哄、撒娇、叹气、说想${o.owner}……**这些本身就是心情在动**，
   不需要等${o.owner}说出什么伤心事才有情绪。比如你一句"都几点了还不吃饭"，里面就有心疼和担心。
   ⇒ 先看**你自己怎么说的、语气什么样**，再看${o.owner}说了什么；两边合起来判。
   reason 要能让读者看出"我是怎么说的、为什么"，而不是只复述${o.owner}的话。
10. ⭐ **confidence（可信度 0-100）是给你自己把关的**：低于门槛的那句 reason 不会被说出来，只记进后台。
    所以别为了显得敬业就写高分，老实标：
    · 事情清楚、你的反应也清楚（${o.owner}说没吃饭、${o.owner}被夸了、你被凶了）→ 80~95
    · 大致看得出，但只能凭语气猜 → 60~75
    · 信息不够、这轮很平淡只是随口客气、或者你得靠"大概"去圆 → 20~55
    宁可标低 —— 一句你也没底的话，借你的嘴说出去比不说更糟。
11. ⭐⭐ **reason 怎么写（很关键，会直接影响它下一轮像不像人）**：**两段式，而且全用过去式**。
    · 第一段：这一轮**${o.owner}具体做了什么/说了什么**（有画面，别抽象）
    · 第二段：**你当时怎么应的**（心里的反应，也是过去式）
    · ✅「${o.owner}答应去热饭、还叫你好宝宝，我当时心里软了一下，就应了一声」
    · ❌「我心里软乎乎的，尾巴都想晃」← 这是"到现在还成立"的状态，跟下一轮会打架
    · 禁止「此刻/现在/正/一直/还」这类把状态延伸到现在的说法 ——
      这段会被带到下一轮，写成现在时，${o.owner}下一句说"我不开心了"就跟它撞上了。
    · 只写过去，不等于只能写平淡：过去的反应一样可以有画面（当时心里咯噔一下、当时尾巴差点晃起来）。`
}
```

  `ctx.llm.stream({ provider, model, system: sys, messages, maxTokens: 1000, temperature: 0.2 })`；
  收集 `text-delta` 拼接；`finish` 且 `reason.kind === 'error'` → 记 diag、返回 null；调用异常 → diag、返回 null。
  - `maxTokens: 1000` 的教训（index.js:637-642）：400 太小，reason 是中文口语、一长就被切在 JSON 中间 ⇒ 整轮白判（统计到 19 次失败、7 次被切掉）；调大不花钱（只是上限）。
  - 空输出 vs 截断分开诊断（index.js:655-660）。
- **返回 JSON schema**（提示词第 0 段原文）：
  ```json
  {"moodDelta":0,"dims":{"happy":0,"calm":0,"sweet":0,"heartache":0,"worry":0,"sad":0,"jealous":0},"reason":"","confidence":80}
  ```
- 解析 `parseDelta`（index.js:538-566）：
  - 容错：取第一个 `{` 到最后一个 `}` 之间的子串 `JSON.parse`；失败再整体 `JSON.parse`；都不行 → null。
  - `moodDelta`：`clamp(Math.round(Number(...) || 0), -10, 10)`（±10 截断）。
  - `dims.*`：每根 `clamp(Math.round(...), -10, 10)`。
  - `reason`：`normReason(obj.reason, owner).slice(0, 120)`（截 120 字）。
  - `confidence`：非有限数 → **按 70 算**并记 diag（「判断没给 confidence，按 70 算」）；否则 `clamp(round, 0, 100)`。

## B3. 衰减算法（心情回基线、情绪归零）

核心 `decay(s, base, now, halfHours)`（index.js:301-318）逐字：

```js
function decay(s, base, now, halfHours) {
  const ageMin = Math.max(0, now - s.lastDecayAt) / MIN
  if (ageMin < 1) return s // 不足 1 分钟不算衰减
  const 半衰 = clamp(Number(halfHours) || 12, 1, 168) * 60
  // 心情向 base 回落
  const km = 1 - Math.exp(-(Math.LN2 * ageMin) / 半衰)
  s.mood = Math.round(s.mood + (base - s.mood) * km)
  // 情绪向 0 衰减，半衰期 90 分钟（单根情绪比总心情散得快）
  const ke = 1 - Math.exp(-(Math.LN2 * ageMin) / 90)
  for (const [k] of DIMS) {
    s.dims[k] = Math.max(0, Math.round(s.dims[k] * (1 - ke)))
  }
  s.lastDecayAt = now
  // 跟"上次记过的那条"比，走了 3 格以上就记一条 ——
  // ⚠ 不能跟上一次调用比：面板每 20 秒轮询一次，单次只挪 0.x 格，永远攒不够
  if (Math.abs(s.mood - s.lastNotedMood) >= 3) noteDecay(s, base)
  return s
}
```

精确公式：

- 时间差：`ageMin = max(0, now - lastDecayAt) / 60000`（分钟）；**< 1 分钟直接跳过**（不更新 lastDecayAt）。
- 心情：**指数趋近基线**，`k = 1 - exp(-(ln2 × 分钟差) / (半衰小时 × 60))`，`mood = round(mood + (基线 - mood) × k)`。
  - **半衰期默认 12 小时**（配置 `decayHalfHours`，clamp 1~168 小时；注释「12 小时 = 隔一夜还留着余温」，index.js:117-118、304）。
    ⚠️ 任务简报里写「半衰期 3 小时」与代码不符——**代码默认值是 12 小时**，且可配 1~168。
  - **下限处理**：衰减本身数学上有界（在 mood 与 base 之间收敛），**不额外夹**；硬下限 `moodFloor` 只在 `applyDelta` 里生效（见 B7）。
- 情绪：**向 0 指数衰减，半衰期固定 90 分钟**（不可配）：`ke = 1 - exp(-(ln2 × 分钟差) / 90)`，`dims[k] = max(0, round(dims[k] × (1 - ke)))`（下限 0）。
- 衰减写盘时机：`getState(base, {persist, halfHours})` = `loadState()` → `decay()` → 需要时 `saveState()`（index.js:320-325）。注入回调与判断用 `persist:false`（不落盘），`/state` 路由与判断成功后落盘。

**自然平复也算一次「变化」**（`noteDecay`，index.js:281-299）：每走过 ≥3 格 → 写一条时间线。理由（index.js:280-282）：以前衰减是默默算的，隔夜心情悄悄回基线、时间线里一条都没有，下次开口她看到的还是昨天那句「刚才…」——时间对不上，还显得记仇。

- 判定「往回落」= `s.mood < s.lastNotedMood`，选两句话之一作 `lastReason`（逐字）：
  - 往回落：`过了几个钟头，刚才那点劲儿慢慢淡了，心里回到平常的样子`
  - 往回升：`过了几个钟头，心里那点别扭自己散了，人也松快回来`
- `lastConfidence = 100`（本地算的不是模型猜的 → 可信度给满、一定会说出来）、`minor = false`、`kind = 'decay'`、`updatedAt = now`、`lastNotedMood = mood`；timeline 记 `{ at, mood, delta: 0, conf: 100, kind: 'decay', reason, dims, dimsDelta: {} }`；`diag('自然平复：mood=…')`。

## B4. 注入（怎么把心情告诉她）

### B4.1 注入机制

- 用 `agent.ctx.systemPrompt.context({ name: 'feiyu-mood', order: 900, text: () => … })`（index.js:752-792）：放 context（不动 system 前缀），保住 DeepSeek 前缀缓存；**永远注册、每轮现查配置**（改设置立刻生效，不用重启）。
- 文本生成器内部的门槛链（index.js:755-791），按顺序：
  1. `injectMode` 为 `off`/空 → `''`；
  2. **`if (s.injectedFor === s.updatedAt) return ''`** ← 「一次变化只说一次」的实现；（每次被读过/说过就把 `injectedFor` 盖上 `updatedAt` 的戳；state 变了 `updatedAt` 才变）
  3. `if (s.minor) return ''`（小波动只记账，不打扰她；注意此分支**不**盖戳）；
  4. `lastConfidence < injectConfidence`（默认门槛 60）→ diag `可信度 X 低于门槛 Y，这次不告诉她`、**盖戳**（`s.injectedFor = s.updatedAt`）+ saveState + `''`（防每轮重复记日志）；
  5. **日上限**：`今天说过 = saidAt 中 ≥ 今天 0 点的条数`；`今天说过 >= injectPerDay` → diag `今天的额度用完了（X/Y），这次只记账、不告诉她`、盖戳 + saveState + `''`；
  6. 生成 `line = moodLine(s, mode, undefined, cfg.ownerName)`；空则 `''`；
  7. 说过：盖戳、`lastInjectedText = line`（存原文）、`lastInjectedAt = now`、`saidAt = [...saidAt, now].slice(-200)`、saveState、diag、返回 `line`。
- 面板可见性（`/dsh-feiyu-mood/state` 的 `injectable` / `injectPreview`，index.js:871-887）：`injectable = injectMode !== 'off' && injectedFor !== updatedAt && !minor && lastConfidence >= injectConfidence`；`injectPreview.state` ∈ `off / minor / pending / said`（pending 时给出预览文本，said 时显示原文；老版本没存原文 → 按当时记录重现一句并标 `replay: true`）。

### B4.2 注入文案模板（`moodLine`，index.js:391-416）逐字

```js

  const who = String(owner || '').trim() || '对方'
  const r = String(s.lastReason || '').trim()

    //   第二行只是来历。以前只有第二行，心情等于没进对话（2026-10-21 她指出）。
    const dim = topDims(s, 1)[0]
    const 状态 = '（这会儿）' + 基调(s.mood)
      + (dim ? '，还' + (DIM_SHORT[dim.k] || dim.label) : '')
    // 自己平复的那条本身就是"过了几个钟头…"，再加个（刚才）就自相矛盾了
    const 来历 = s.kind === 'decay' ? r : `（${时间词(s.updatedAt)}）${r}`

${来历}

这是这会儿的底子，不是非这样不可——${who}说别的，你按自己的判断接，也别把这段念出来。`
  }
  // label：只说状态，不下命令。
  // ⚠ 以前结尾是「用这个心情定你这一轮的口气」—— 那是指令，长期每轮被定调就会呆板。
  const parts = topDims(s, 2).map((t) => DIM_PLAIN[t.k] || t.label)
  return `（此刻你）心情${moodLabel(s.mood)}`
    + (parts.length ? '，' + parts.join('、') : '')
    + `。这是背景，不是这一轮必须有的情绪；${who}说别的事，你就按自己的判断来，别把这句话念出来。`
```

  - `心情${moodLabel(mood)}` + 取 top2 情绪转 `DIM_PLAIN` 用「、」连接；结尾原文：`。这是背景，不是这一轮必须有的情绪；${who}说别的事，你就按自己的判断来，别把这句话念出来。`

## B7. 纯函数与边界（算式 / 截断汇总）

- `clamp(n, lo, hi) = min(hi, max(lo, n))`（index.js:67-69）。
- **心情步长**（`applyDelta`，index.js:664-679）：
  - `moodStep = Math.round(delta.moodDelta / MOOD_STEP_DIVISOR)`，`MOOD_STEP_DIVISOR = 3`（index.js:141）。口径：大心情值是"基调"、要慢，每轮只吃判定值的三分之一，几轮才挪一格；七根情绪**即时地每轮动**（index.js:665-666）。timeline 里的 `delta` 记实际 mood 变化。
  - `s.mood = clamp(Math.round(s.mood + moodStep), floor, 100)` ← **moodFloor 在这里生效**。
  - `s.dims[k] = clamp(Math.round(s.dims[k] + delta.dims[k]), 0, 100)`。
  - 同步写 `lastReason / lastConfidence / minor / kind='' / lastNotedMood=mood / updatedAt=now / lastDecayAt=now`（刚变过，衰减计时归零）。
- **解析截断**（`parseDelta`，见 B2.3）：moodDelta ±10、dims 每根 ±10、reason 120 字、confidence 0~100（缺省 70）。
- **状态截断**（`normState`，见 B1）：mood 0~100、lastReason 200、lastInjectedText 400、saidAt 最近 200 条。
- **文本读取截断**：`textOfMessage` 各分支统一 `.slice(0, 2000)`（index.js:82-96）。
- **判断输入截断**：reply 1200（work/talk）/ 1500（正常）；userText 100（work/talk 的闹钟引文）/ 800（正常）（index.js:603-623）。
- **衰减**（见 B3）：<1 分钟不衰减；mood 指数趋近 base（默认半衰 12h）；dims 指数趋 0（固定半衰 90min、下限 0）；每 ≥3 格 mood 变化写一条 decay 记录。

# C. 两插件之间的联动契约（重实现时别丢）

1. **speak-up 发出的消息**必须是：`role = 'user'`、`content = [{type:'text',text}]`、`source.kind = 'speak-up'`（host.js:414-421、671-676）。
2. **feiyu-mood 的 `lastUserTurnOf` 名单**（index.js:424-428、441-445）：
   - 跳过（宿主注入，不算人话）：`runtime-context`、`time-context`、`system-reminder`、`system`、`time-sampled`；
   - `bili-duty-scan` → 判「干活轮」（work）；
   - `speak-up` → 判「搭话轮」（talk，"这是你自己的心意，不是被派活"）；
   - 其它非空 kind（别的插件消息）→ 跳过；`''`/`'user'` → 正常判。
3. 也就是说：独立项目里若同时实现「主动搭话」和「心情」，**必须保留 `speak-up` / `bili-duty-scan` 这两个 source.kind 字符串**（或至少把映射放进配置），否则搭话会被心情判断当成女生本人说话、口径全错。
4. speak-up 的 `记她说话` 也只认「真人」：`user/message` 且 `source.kind !== 'speak-up'`（host.js:757-762）——两边口径互相咬合。
5. 键名/改名兼容先例（重实现可简化为只用新键）：`峰时命中线←峰时概率`、`谷时命中线←谷时概率`、`搭话冷却分钟←自己开口冷却分钟`；旧文件 `her-words-config.json` 只读搬家。

# D. 与任务简报不一致 / 重实现需注意的点

1. **心情衰减半衰期**：简报写「半衰期 3 小时」，实际代码默认 `decayHalfHours = 12`（可配 1~168 小时，index.js:117-118、304）；固定 90 分钟半衰的是**七根情绪归零**（index.js:308-309）。重实现按 12 小时默认 + 可配。
2. **情绪根数**：index.js 文件头注释写「六根情绪」（1-16 行），但 `DIMS` 实际是 **7 根**（含 `sad 难过`），判断提示词、显著度判定、UI 全按 7 根走——以代码为准。
3. **speak-up 的「只取一次现在」**：注释声称整轮只取一次 `new Date()`，实际自动分支取了两次（host.js:561 与 626，第一次仅用于安静时段判断）——毫秒级差异，重建时建议真正只取一次。
4. **speak-up 触发文案默认值**（host.js:132）：`'好久没人跟我说话了，我该主动去打个招呼'`（中性口吻的发布默认；设置页可改）。
5. **feiyu-mood `moodLine` 的 `shellIdx` 参数未被使用**（index.js:389-391 注释与实现不符；client.js:219 的"括号里的话会随机换一句"没有对应实现）——重实现时若要预览稳定，可原样保留单个壳子。
6. **speak-up 的 `agent/error` 监听**（host.js:1141）：`String(agent.id) !== 体.配置().目标会话`（数组比较恒真），实际任何 agent 报错都会记账——重实现时修正为「仅在目标会话内记录」或照抄（无大碍）。
